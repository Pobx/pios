# Phase 1.1 — PostgreSQL Schema Design & Data Migration Rules

## 1. Source of Truth
- **Source Dump**: `docs/u709955349_optconnect.sql` (MariaDB 11.8.9 production snapshot, 110 tables, 137 foreign keys).
- **Converter**: `tools/mysql2pg/convert.py` (DDL generator) and `tools/mysql2pg/load_data.py` (ETL data loader).
- **Generated Migration**: `backend-go/db/migrations/000001_baseline.{up,down}.sql` + `schema_report.json`.

## 2. Data Type Mapping Rules (MariaDB/MySQL → PostgreSQL 16)

| MySQL / MariaDB Type | PostgreSQL 16 Type | Rationale & Notes |
|---|---|---|
| `TINYINT(1)` | `BOOLEAN` | 18 columns converted; defaults `'0'`/`'1'` mapped to `FALSE`/`TRUE` |
| `TINYINT(3/4)` | `SMALLINT` | Non-boolean small integers |
| `SMALLINT UNSIGNED` | `INTEGER` | Widened to prevent overflow |
| `INT` | `INTEGER` | Standard 32-bit signed integer |
| `INT UNSIGNED` | `BIGINT` | Widened to prevent unsigned overflow |
| `BIGINT` / `BIGINT UNSIGNED` | `BIGINT` | Primary keys & foreign keys (306 columns) |
| `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` | Standard SQL identity columns (99 columns); sequences reset post-load |
| `DECIMAL(m,n)` | `NUMERIC(m,n)` | Exact monetary/quantity representation (75 columns) |
| `FLOAT` | `NUMERIC(18,4)` | MySQL `float` was used on monetary columns (`deposit`, `payrate_permonth`, `vat`); upgraded to exact `NUMERIC` (38 columns) |
| `DOUBLE` | `DOUBLE PRECISION` | Used for sensor/weight aggregates (4 columns) |
| `VARCHAR(n)` / `CHAR(n)` | `VARCHAR(n)` / `CHAR(n)` | Direct mapping |
| `TEXT` / `LONGTEXT` | `TEXT` | Direct mapping |
| `ENUM(...)` | `TEXT` + `CHECK (col IN (...))` | Avoids rigid PG enum types while enforcing domain values (65 columns) |
| `TIMESTAMP` | `TIMESTAMPTZ` | Laravel `config/app.php` uses UTC; stored with timezone awareness (219 columns) |
| `DATETIME` | `TIMESTAMP` | Local timestamp without timezone (1 column) |
| `DATE` / `TIME` | `DATE` / `TIME` | Zero-dates (`0000-00-00`) sanitized to `NULL` during load |
| `ON UPDATE current_timestamp()` | `BEFORE UPDATE` trigger `set_updated_at()` | PL/pgSQL trigger function automatically updates `updated_at` |

## 3. Foreign Keys & Composite Key Fixes
- All **137 Foreign Keys** from the production dump are preserved with their original `ON DELETE` / `ON UPDATE` actions.
- **Composite PK Prefix Issue (`tambons`)**: In MariaDB, `tambons` has `PRIMARY KEY (id, district_id)` while `organizations.org_tambon_id_fk` and `users.tambon_code` reference `tambons(id)`. PostgreSQL requires referenced columns to have a full `UNIQUE` constraint. The converter automatically detects this and synthesizes `ALTER TABLE tambons ADD CONSTRAINT tambons_id_key UNIQUE (id);`.

## 4. Multi-Tenancy Normalization
- All 47 tables with `org_id_fk` are normalized to `org_id` in PostgreSQL (`schema_report.json` tracks `renamed_org_id`).
- All indexes and foreign keys referencing `org_id_fk` are rewritten to `org_id`.
